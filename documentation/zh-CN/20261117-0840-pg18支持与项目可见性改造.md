# ShowDoc 改造说明：PostgreSQL 18 存储、默认私密项目、禁用公开项目

适用版本：v3.9.6（当前仓库）。本文只讨论 PostgreSQL 18，不再考虑 MySQL。

## 实施状态

已完成最小端到端：

- `Database::getInstance()` 增加 `pgsql` 分支，默认仍是 SQLite。
- `Upgrade::checkAndUpgrade()` 按驱动分派；PostgreSQL 空库会自动执行 `install/showdoc.pgsql.sql`，列检查改用 `information_schema`。
- `install/showdoc.pgsql.sql` 已生成并实际导入 PostgreSQL 18 验证（49 张表，`db_version_num=36`）。
- `ExportLog` 统一使用 Unix 时间戳；`Security::safeLike()` 支持 PostgreSQL；`Options::set()` 在 PostgreSQL 下改用 upsert。
- `insertGetId()` 的非 `id` 主键（`user.uid`、`page.page_id`、`catalog.cat_id`、`item_member.item_member_id`、`captcha.captcha_id`、`page_comment.comment_id`、`page_feedback.feedback_id`、`upload_file.file_id`）已显式指定主键列。
- `docker-compose.yml` 增加 PostgreSQL 18 profile，默认仍启动 SQLite。
- 默认私密已实现：前端默认私密，后端 `add`/`update`/`import`/MCP 对空密码生成随机密码；显式 `is_open=1` 仍可创建公开项目。

仍待补：

- `LIKE` 大小写：PostgreSQL 下搜索区分大小写，尚未批量改为 `ILIKE`。
- 安装器 UI（`install/`）仍只面向 SQLite；PostgreSQL 依赖环境变量 + 空库自动建 schema。
- `entrypoint.sh` 的每日备份、`AdminUpdateController`/`UpdateController` 的在线更新仍按 SQLite 文件处理；PostgreSQL 需要另外配置 `pg_dump`。
- `Upgrade::updatePgsql()` 目前只覆盖已知的补列（user 的 email/mobile、upload_file.file_size）；后续版本新增结构仍必须补 PostgreSQL 迁移。
- “禁用公开项目”尚未做访问层封死，目前只是默认私密。

`RunapiController` 里的 `mysql/postgresql/sqlite` 是 RunApi 项目连接用户自己的数据库，和 ShowDoc 自身存储无关，不要改混。

## 结论摘要

### 1.2 已实现的代码

1. **连接参数**：`Database::getInstance()` 增加 `pgsql` 分支。

   ```php
   } elseif ($driver === 'pgsql') {
       $capsule->addConnection([
           'driver'   => 'pgsql',
           'host'     => Env::get('DB_HOST', '127.0.0.1'),
           'port'     => (int) Env::get('DB_PORT', 5432),
           'database' => Env::get('DB_NAME', 'showdoc'),
           'username' => Env::get('DB_USER', 'showdoc'),
           'password' => Env::get('DB_PWD', ''),
           'charset'  => Env::get('DB_CHARSET', 'utf8'),
           'prefix'   => '',
           'schema'   => Env::get('DB_SCHEMA', 'public'),
           'sslmode'  => Env::get('DB_SSLMODE', 'prefer'),
           'options'  => [
               \PDO::ATTR_STRINGIFY_FETCHES => true,
           ],
       ]);
   }
   ```

   驱动名必须写 `pgsql`，Laravel 的 PostgreSQL 连接器认这个名字。`PRAGMA busy_timeout` 只保留在 SQLite 分支。

2. **升级器**：`Upgrade::checkAndUpgrade()` 按驱动分派。

   ```php
   $driver = DB::connection()->getDriverName();
   if ($driver === 'pgsql') {
       $result = self::updatePgsql();
   } else {
       $result = self::updateSqlite();
   }
   ```

   `Upgrade::isColumnExist()` 增加 PostgreSQL 分支：

   ```php
   $row = DB::selectOne(
       'SELECT COUNT(*) AS c FROM information_schema.columns
        WHERE table_schema = current_schema() AND table_name = ? AND column_name = ?',
       [$table, $column]
   );
   return (int) ($row->c ?? 0) > 0;
   ```

   新增 `Upgrade::updatePgsql()`，不能直接复用 SQLite 语句，至少处理：
   - `INTEGER PRIMARY KEY AUTOINCREMENT` → `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
   - `INT(11)`、`BIGINT(40)` → `INTEGER`、`BIGINT`（PostgreSQL 不接受显示宽度）
   - `TINYINT(1)` → `SMALLINT`
   - `DATETIME` → `TIMESTAMP`
   - `INSERT OR IGNORE INTO sqlite_sequence ...` → 删除，改用 `setval`
   - `CREATE TABLE IF NOT EXISTS`、`CREATE INDEX IF NOT EXISTS` 可以保留
   - 建表后的自增起点：

     ```sql
     SELECT setval(pg_get_serial_sequence('item', 'item_id'),
                   COALESCE((SELECT MAX(item_id) FROM item), 1));
     ```

   每张有 identity 列的表都要同步一次。

3. **完整 schema**：已新增 `install/showdoc.pgsql.sql`。当前 `Upgrade` 只补列和少量表，基础表 `item/page/catalog/user/...` 不在代码里；schema 文件承担首次建表。

   生成起点（仅用于重新生成时参考）：

   ```bash
   sqlite3 Sqlite/showdoc.db.php ".schema" > tmp/showdoc.sqlite.sql
   ```

   然后按 1.3 的规则逐表转换。不要直接执行转换结果，必须逐列核对类型和默认值。

4. **导出统计**：`ExportLog::getTodayCount()` 和 `getRecentDaysCount()` 已统一用 Unix 时间戳比较，不再依赖数据库日期函数。

   ```php
   public static function getTodayCount(int $uid, string $exportType): int
   {
       if ($uid <= 0) {
           return 0;
       }
       return (int) DB::table('export_log')
           ->where('uid', $uid)
           ->where('export_type', $exportType)
           ->where('addtime', '>=', strtotime('today'))
           ->count();
   }

   public static function getRecentDaysCount(int $uid, string $exportType, int $days = 3): int
   {
       if ($uid <= 0) {
           return 0;
       }
       $start = time() - (($days - 1) * 86400);
       return (int) DB::table('export_log')
           ->where('uid', $uid)
           ->where('export_type', $exportType)
           ->where('addtime', '>=', $start)
           ->count();
   }
   ```

   `addtime` 是整数时间戳，这套写法在 SQLite 和 PostgreSQL 下都成立，也避免数据库时区差异。

5. **LIKE 转义**：`Security::safeLike()` 不能再用 `SQLite3::escapeString()`。

   ```php
   $driver = DB::connection()->getDriverName();
   if ($driver === 'pgsql') {
       $pdo    = DB::connection()->getPdo();
       $quoted = $pdo->quote($s);
       $s      = substr($quoted, 1, -1);
   } elseif (class_exists('\SQLite3')) {
       $s = \SQLite3::escapeString($s);
   } else {
       $s = str_replace('\\', '\\\\', $s);
       $s = str_replace("'", "\\'", $s);
   }
   ```

   拼接 `LIKE` 的 SQL 建议显式加 `ESCAPE '\'`。PostgreSQL 默认转义字符是反斜杠；SQLite 没有默认转义字符，不能依赖同一套 `\%` 行为。

6. **LIKE 大小写**：PostgreSQL 的 `LIKE` 区分大小写，SQLite 默认不区分。用户可见搜索要么改 `ILIKE`，要么改 `LOWER(column) LIKE LOWER(?)`。

   ```php
   $op = DB::connection()->getDriverName() === 'pgsql' ? 'ilike' : 'like';
   $query->where('item_name', $op, "%{$keyword}%");
   ```

   需要检查的位置：

   - `Api\AdminItemController`：项目名、用户名搜索
   - `Api\AdminUserController`：uid、用户名、邮箱、手机号搜索
   - `Api\PublicSquareController::getPublicItems()`：项目名、描述、正文搜索
   - `Api\UserController`：用户搜索
   - `Api\ParamDescLibController`：名称、描述、标签搜索
   - `Api\AttachmentController`：附件名、正文搜索
   - `Mcp\Handler\PageHandler`、`Mcp\Handler\KanbanHandler`：页面标题搜索
   - `Model\UploadFile`：文件名、文件类型搜索

   `Model\Mock` 的 `path LIKE '~%'` 不涉及字母大小写，可以不动。

7. **Options 并发写入**：`Options::set()` 现在是“先查再插/改”。SQLite 单写锁掩盖了这个竞态；PostgreSQL 并发下两个请求可能同时插入同一个 `option_name`，撞唯一键。

   改为 upsert：

   ```php
   return DB::table('options')->upsert(
       [['option_name' => $name, 'option_value' => $value]],
       ['option_name'],
       ['option_value']
   ) >= 0;
   ```

   如果还要兼容很老的 SQLite，可以按驱动分支：PostgreSQL 用 `upsert`，SQLite 保留原逻辑。

8. **Docker 镜像**：`Dockerfile` 增加 `pdo_pgsql`。
   - 官方 `php` 基础镜像：`apk add --no-cache postgresql-dev` 后 `docker-php-ext-install pdo_pgsql`。
   - `webdevops/php-nginx` 基础镜像：使用镜像自带的 `install-php-extensions pdo_pgsql`。
   - `entrypoint.sh` 的 `--build` 阶段增加 `pg_dump`、`pg_isready`，版本必须不低于服务端主版本。
   - 如果 Alpine 的 `postgresql-client` 版本低于 18，改用 `postgres:18` 镜像执行备份，不要混用低版本 `pg_dump`。

9. **备份**：`entrypoint.sh` 的 `backup_dbfile()` 和每日备份循环按 `DB_TYPE` 分支。

   ```sh
   # PostgreSQL
   export PGHOST="$DB_HOST" PGPORT="$DB_PORT" PGUSER="$DB_USER" PGPASSWORD="$DB_PWD"
   pg_dump --format=custom --no-owner --no-privileges \
       --file="$backup_file" "$DB_NAME"
   ```

   恢复：

   ```sh
   pg_restore --clean --if-exists --no-owner -d "$DB_NAME" "$backup_file"
   ```

   密码用 `PGPASSWORD` 环境变量，不要放进命令行参数。

10. **在线更新**：`AdminUpdateController::download()`、`updateFiles()` 和 `UpdateController::dockerUpdateCode()` 把 `Env::get('DB_NAME')` 当文件路径，PostgreSQL 下这是库名。

    - 按 `DB_TYPE` 跳过 SQLite 文件备份和 `Sqlite/` 写权限检查。
    - 更新前执行 `pg_dump`，失败则中止更新。
    - 回滚用 `pg_restore`，并注意代码版本与 schema 版本要匹配。
    - `UpdateController::checkDb()` 同样按驱动分支。

### 1.3 Schema 转换规则

从 SQLite 导出后逐表处理：

| SQLite | PostgreSQL 18 | 说明 |
| --- | --- | --- |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | 不要用 `SERIAL`，identity 更标准 |
| `INT(11)`、`BIGINT(40)` | `INTEGER`、`BIGINT` | PostgreSQL 不接受类型显示宽度 |
| `TINYINT(1)` | `SMALLINT` | 代码用 0/1，不要改 boolean |
| `DATETIME` | `TIMESTAMP` | 代码存字符串时间，类型要兼容 |
| `BLOB` | `BYTEA` | 当前代码不读写 `user.cookie_token`，也可以直接改 `TEXT` |
| `CHAR(n)` | `VARCHAR(n)` 或 `TEXT` | 见下面的补空格坑 |
| `TEXT NOT NULL DEFAULT ''` | `TEXT NOT NULL DEFAULT ''` | PostgreSQL 支持，和 MySQL 不同 |
| `sqlite_sequence` | 不创建 | 用 `setval` 同步序列 |
| `CREATE TABLE "<?php "` | 删除 | SQLite 文件头造成的垃圾表 |
| `item_password_bak_*` | 不创建 | 运维临时表，不迁移 |

必须特别注意：

- **`options.option_name` 和 `options.option_value` 不能保留 `CHAR(200)`**。PostgreSQL 的 `CHAR(n)` 会补尾随空格，`Options::get()` 返回的 `option_value` 可能变成带空格的字符串，代码里的 `=== '0'`、`!== '1'` 判断会失效。改成 `VARCHAR(200)` 和 `TEXT`。
- `options.option_value` 存过 AI 配置、LDAP JSON、OSS 配置，长度可能超过 200，必须 `TEXT`。
- `user_token.token`、`template.template_title` 等原 `CHAR(200)` 字段统一改 `VARCHAR`/`TEXT`。
- `user` 是 SQL 关键字。Illuminate 会自动加双引号，但手写 raw SQL 时表名要写 `"user"`。
- `item.item_id`、`page.page_id`、`catalog.cat_id` 是显式 ID 和自增混用。建表用 identity，迁移数据后必须 `setval`；否则后续自增插入会从 1 开始并撞主键。
- 索引：`item(uid)`、`item(item_domain)`、`page(item_id)`、`catalog(item_id)`、`item_member(item_id, uid)`、`team_item_member(item_id, member_uid)`、`user(username)`。PostgreSQL 不支持前缀索引；长文本索引用表达式索引，或把被索引列改 `VARCHAR(255)`。
- 保留 `options.option_name` 的 `UNIQUE`，`Options::set()` 的 upsert 依赖它。

### 1.4 数据迁移（旧 SQLite → PostgreSQL）

不做 web 页面按钮。迁移是一次性、破坏性的运维操作，用 shell 脚本停机执行，便于备份、校验和回滚，也不会多出一个可匿名访问的接口。

前置：

- 旧库位于 `showdocdata/html/Sqlite/showdoc.db.php`。
- `.env` 已配置 `DB_TYPE=pgsql`、`DB_NAME`、`DB_PWD`。
- 目标 PostgreSQL 可以是空库；如果是非空库，必须加 `--force`，脚本会清空目标表后重新导入。

执行：

```bash
chmod +x documentation/scripts/migrate-sqlite-to-pgsql.sh
./documentation/scripts/migrate-sqlite-to-pgsql.sh

# 目标库已有项目、确认要覆盖时
./documentation/scripts/migrate-sqlite-to-pgsql.sh --force
```

脚本会：

1. 备份 SQLite 到 `showdocdata/backup/sqlite-<时间>.db`。
2. 用 `pg_dump` 备份目标 PostgreSQL 到 `showdocdata/backup/pg-<时间>.sql`。
3. 停止 showdoc，避免迁移期间写入。
4. 在 showdoc 容器内执行 `documentation/scripts/migrate-sqlite-to-pgsql.php`：
   - 空库自动执行 `install/showdoc.pgsql.sql`。
   - 按 `information_schema` 和 `PRAGMA table_info` 取交集列，跳过新版本不存在的旧表/旧列。
   - 转换时间戳、整数、BLOB/TEXT，清掉 PostgreSQL 不接受的 NUL。
   - 导入后把 `options.db_version_num` 写成 36，并同步所有 identity 序列。
   - 逐表对比 source/target 行数，输出 `ok` 或 `MISMATCH`。
5. 启动 showdoc。

注意：

- 脚本按当前 `install/showdoc.pgsql.sql` 的 schema 导入；旧库没有的新表会保持空表，旧库多出的表会跳过并打印。
- 迁移前建议在 SQLite 副本上演练一次；脚本会清空目标表，不能对生产 PostgreSQL 反复试。
- 如果旧库里有大量 `export_log` 日期字符串，脚本会尽量转成时间戳，转不了的记为 0；导出日志不影响文档数据。

6. 启动应用，触发 `Upgrade::checkAndUpgrade()`。确认 `options.db_version_num` 等于 `Upgrade::CURRENT_VERSION`。
7. 创建管理员：执行 `php index.php home/common/repasswd`。注册接口创建的用户默认 `groupid=2`，不是管理员。

### 1.5 PostgreSQL 18 部署

`docker-compose.yml` 示例：

```yaml
services:
  postgres:
    image: postgres:18
    profiles: ["postgres"]
    environment:
      POSTGRES_DB: ${DB_NAME:-showdoc}
      POSTGRES_USER: ${DB_USER:-showdoc}
      POSTGRES_PASSWORD: ${DB_PWD:-showdoc_change_me}
    volumes:
      - ./showdocdata/postgresql:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER:-showdoc} -d ${DB_NAME:-showdoc}"]
      interval: 5s
      timeout: 3s
      retries: 20
    restart: always

  showdoc:
    depends_on:
      postgres:
        condition: service_healthy
        required: false
    environment:
      DB_TYPE: ${DB_TYPE:-sqlite}
      DB_HOST: ${DB_HOST:-postgres}
      DB_PORT: ${DB_PORT:-5432}
      DB_NAME: ${DB_NAME:-showdoc}
      DB_USER: ${DB_USER:-showdoc}
      DB_PWD: ${DB_PWD:-showdoc_change_me}
      DB_SCHEMA: ${DB_SCHEMA:-public}
    restart: always
```

默认 `docker compose up -d` 仍然只启动 showdoc + SQLite；启用 PostgreSQL 用 `docker compose --profile postgres up -d`，并在 `.env` 设置 `DB_TYPE=pgsql`、`DB_NAME`、`DB_PWD`。

关键点：PostgreSQL 18 官方镜像的 `PGDATA` 是 `/var/lib/postgresql/18/docker`，目录要挂到 **`/var/lib/postgresql`**。继续挂 `/var/lib/postgresql/data` 会启动失败。这里和 `./showdocdata/html` 一样使用宿主机目录，不使用 named volume。

宿主机目录必须先让容器内的 postgres 用户可写：

```bash
mkdir -p showdocdata/postgresql
chmod 777 showdocdata/postgresql
# Linux 也可以用: chown -R 999:999 showdocdata/postgresql
```

如果目录已经存在但属主不是当前用户，先删掉重建。本地修改代码并重建镜像后，还要执行 `rm -f showdocdata/html/.ver`，否则 entrypoint 会因为版本号相同跳过代码同步。

### 1.7 风险

- `LIKE` 大小写：尚未改 `ILIKE`，英文搜索会从“不区分大小写”变成“区分大小写”。
- `GROUP BY`：PostgreSQL 比 SQLite 严格，所有非聚合列必须出现在 `GROUP BY`。现有 `PublicSquareController`、`AiChatMessage` 看起来合法，仍要跑测试。
- 并发创建项目：`Item::getANewItemId()` 仍是 `MAX(item_id) + rand`，高并发下可能撞主键，需要重试或序列化。
- `pg_dump` 版本低于 18 时，对 18 服务端备份可能失败或不可靠。
- 连接数：PHP-FPM 每请求一条连接，PostgreSQL 默认 `max_connections=100`；高并发需要 PgBouncer 或调参。
- 时区：`ExportLog` 按应用时区计算时间戳，避免数据库时区差异；`TIMESTAMP` 列仍要确认读写时区。
- 升级：`Upgrade::updatePgsql()` 目前只补已知的 user/upload_file 列；后续版本新增结构必须在里面补 PostgreSQL 迁移。
- 默认私密是代码层行为，不再使用 SQLite 触发器；`showdocdata/20261117-0827-showdoc-force-private-triggers.sql` 不要执行。

## 二、默认私密项目（已实现）

### 2.1 改动前

- `web_src/src/views/modals/item/CreateItemModal/index.vue`：`isOpenItem = ref(true)`。
- `web_src/src/views/modals/item/CopyItemModal/index.vue`：`isOpenItem = ref(true)`。
- 后端 `Api\ItemController::add()` 不校验 `password`，空字符串直接落库。

- `Mcp\Handler\ItemHandler::createItem()` 读取 `$params['password']`，但 MCP 工具 `create_item` 的 schema 没有 `password` 参数，MCP 创建的项目必然公开。

### 2.2 当前实现

1. `CreateItemModal/index.vue`：`isOpenItem` 和 `initCreateForm()` 默认都是 `false`；提交时带 `is_open: isOpenItem ? 1 : 0`。
2. `CopyItemModal/index.vue`：`isOpenItem` 默认 `false`；提交时同样带 `is_open`。
3. `Api\ItemController::add()`：

   ```php
   $isOpen = (int) $this->getParam($request, 'is_open', 0);
   if ($password === '' && !$isOpen) {
       $password = \App\Common\Helper\FileHelper::getRandStr();
   }
   ```

   显式 `is_open=1` 时保留空密码，允许创建公开项目。

4. 复制分支：默认生成随机密码；`is_open=1` 的副本在 `Item::copy()` 后清空密码，显式恢复公开。
5. `Mcp\Handler\ItemHandler::createItem()`：`password` 参数可省略，省略时生成随机密码；`McpServer` 的 `create_item` schema 已补 `password` 参数。
6. `Model\Item::import()`：新建项目时密码为空则生成随机密码。
7. `Api\ItemController::update()`：未传新密码且未显式 `is_open=1` 时保留原密码，避免只改项目名把私密项目变成公开。

### 2.3 验收

- 新建项目默认是“私密项目”，必须填密码才能提交。
- 不填密码直接调 `POST /api/item/add`，返回的项目 `password` 非空，匿名访问被拒。
- 复制公开项目时，新项目不会继承公开状态。
- MCP `create_item` 创建的项目不是公开项目。

## 三、如何禁用公开项目

“禁用公开项目”不等于“默认私密”。默认私密只是 UI 默认，用户仍能主动创建公开项目，旧项目也仍然公开。彻底禁用需要同时做四层。

### 3.1 服务端创建入口强制

所有创建/修改项目的地方都拒绝空密码：

1. `Api\ItemController::add()`：`password` 为空直接返回错误。
2. `Api\ItemController::update()`：禁止把已有项目改成公开。当前 `update()` 直接覆盖 `password`，传空即变公开；改为空密码返回参数错误。
3. `Model\Item::import()`：新建项目时空密码返回 `false`。
4. `Mcp\Handler\ItemHandler::createItem()`：空密码抛参数错误；同时把 `password` 加入 `create_item` 的必填字段。
5. `Api\ItemController::updateByApi()` 走 `OpenController::updateItem()` → `updatePage()`，只更新页面内容，不涉及项目密码，不需要改。

只改前端不够，`/api/item/add`、`/api/item/update`、MCP、导入接口都能绕过。

### 3.2 访问层封死存量公开项目

存量项目 `password` 仍为空，仅靠创建校验封不住。改 `BaseController::checkItemVisit()`：

```php
$item = \App\Model\Item::findById($itemId);
if (!$item) {
    return false;
}

// 禁用公开项目：无密码项目只允许创建者/成员访问
if (empty($item->password)) {
    return false;
}

return (string) $item->password === (string) ($_REQUEST['_item_pwd'] ?? '');
```

创建者、项目管理员、成员在函数前面已经 `checkItemManage()` / 成员查询返回 `true`，所以登录后的正常协作不受影响；匿名用户和非成员一律拒绝。

同时关闭 SEO 渲染，否则 `/123`、`/page/456` 仍会直接输出存量公开项目正文：

- `App\Home\Controller\ItemController::show()`：开头直接 `return $this->fallbackWeb($response);`，不再渲染正文。
- `App\Home\Controller\PageController::show()`：同样直接兜底。
- 或者删除 `index.php` 中 `/{item_id:\d+}` 和 `/page/{page_id:\d+}` 两条渲染路由，保留 SPA 路由即可。

### 3.3 存量数据处置

访问层封死后，存量公开项目对匿名用户立即失效。是否改数据取决于产品策略：

- 不改数据：创建者登录后仍能访问，需要分享时自行设置密码。改动最小，可逆。
- 批量加随机密码（不推荐）：创建者不知道随机密码，需要逐个进项目详情查看。

统计存量公开项目：

```sql
SELECT item_id, item_name, uid
FROM item
WHERE is_del = 0 AND (password IS NULL OR password = '');
```

### 3.4 关闭公开广场

公开广场开关是 `options.enable_public_square`，默认 `0`。

1. 后台“系统设置 → 启用公共广场”关闭；或写库：

   ```sql
   INSERT INTO options (option_name, option_value)
   VALUES ('enable_public_square', '0')
   ON CONFLICT (option_name)
   DO UPDATE SET option_value = EXCLUDED.option_value;
   ```

2. 后端已经生效：
   - `PublicSquareController::checkEnabled()` 返回 `enable=0`。
   - `PublicSquareController::getPublicItems()` 返回“公开广场功能未启用”。
3. 前端入口：
   - `web_src/src/views/item/home/HeaderRight.vue` 受 `checkEnabled` 控制，关闭后自动隐藏。
   - `web_src/src/views/landing/Index.vue` 在 `home_page == 4` 时跳转 `/public-square/index`；如果后台首页设置仍是“公开广场”，改成“首页”或“登录页”，否则用户访问首页会被送到一个空页面。

   ```sql
   UPDATE options SET option_value = '1'
   WHERE option_name = 'home_page' AND option_value = '4';
   ```

4. 可选：删除 `web_src/src/router/index.ts` 中的 `/public-square/index` 路由和 `web_src/src/views/public-square/` 目录，彻底移除入口。
5. 若要在代码层强制禁用（防止后台误开），在 `AdminSettingController` 保存设置时忽略 `enable_public_square`，固定写 `0`。

### 3.5 验收清单

- 未登录访问存量公开项目 `/<item_id>`、`/page/<page_id>`：不返回正文。
- 未登录调 `/api/page/show`、`/api/item/info` 等页面接口：返回无权限。
- 登录创建者访问自己的项目：正常。
- 登录项目成员访问成员项目：正常。
- 创建项目不填密码：前端拦截，直接调 API 返回错误。
- MCP `create_item` 不传密码：返回参数错误。
- 公开广场接口返回未启用，前端入口不显示。
- 站点首页不再因为 `home_page=4` 跳到空广场。

## 四、建议实施顺序

1. 先做“默认私密”（前端默认值 + 后端创建校验），影响面小，可独立上线。
2. 再做“禁用公开项目”的访问层封口（`checkItemVisit` + SSR 兜底），先封匿名访问，不动存量数据。
3. 最后做 PostgreSQL 18。先在一个空库上跑通“建 schema → 启动 → 注册/登录 → 建项目/页面 → 备份恢复”，再迁移真实数据。
4. PostgreSQL 的 `LIKE` 大小写、`options` 字段类型、序列同步三项必须在上线前逐项验证，它们不会在启动时报错，只会在使用中表现为搜索异常、设置不生效、主键冲突。
